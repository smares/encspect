**The problem.** WavPack 4, out by September 2004, changed the file format. The files WavPack 1.0 to 3.97 wrote from 1998 to 2003 are still around, and no specification of them exists beyond the sources and the programs' documents.

**How it works.** A file of these versions is not made of blocks. It starts with the header of the source WAV file, copied unchanged up to the data chunk's header, so the sizes in it are the source's. A WavPack header follows: 10 bytes in version 1, 12 in version 2 and 36 in version 3, with the version, from version 2 a limit on the bits spent on a sample or, in hybrid mode, a target, and in version 3 the flags, the number of samples and a check of the audio. One bitstream codes the whole audio, and nothing in the file says where it ends: a decoder reads until it has the samples the header states. Where the source had bytes after its audio, an encoder may keep them after the bitstream behind 16 bytes of 0xFF. A hybrid file of version 3 with the new high flag has its correction data in a second file with no header at all. A raw file, made from audio with no WAV header, starts with the WavPack header.

**What you see.** The stored WAV header, the WavPack header with its flags, the bitstream and, where it chains to the end of the file, the trailer. The speed mode and the stereo coding come from the flags. Without decoding the analyzer cannot compare the check, tell where the bitstream ends or read the audio, so the average bitrate counts the bytes up to the trailer. When the file is decoded, the analyzer compares the check of a version 3 file, finds where the last sample's bits end and compares that with where it placed the trailer; beside its correction file the pair is decoded and the header's second check, of the lossless audio, compared ([correction files](correction-files)). In Encspect's test files WavPack 1.0 to 3.2 drop chunks after the audio and 3.4 and 3.97 keep them in a trailer; the analyzer does not use this to name a release. libwavpack since 5.0 reads these files only if built with its legacy option, which the Debian packages of 5.6.0 and 5.9.0 leave off.
